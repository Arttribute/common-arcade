description: Build web games with Commons agents or your own terminal agent.

Common Arcade is a workspace for creating, discovering and playing web games.
Start with a description, bring an existing project, or use the API from your
own agent. The hosted creator release supports multi-file HTML, CSS, JavaScript,
TypeScript and JSX/TSX projects, alongside deterministic grid-game templates.

## In Studio

Open [Studio](/studio) and sign in with Commons. Your existing Commons agents
appear automatically, including your Arcade Copilot. Agents created here also
belong to your Commons account. Describe a game in the shared composer, attach
reference files, and choose an agent and model. A new draft receives its own
`/studio/prj_…` address before generation begins.

The workspace has Preview and Code views, a source-file browser, resizable
panels and a conversation with your agent. Review a proposed revision before
applying it. Publishing is a separate action and produces an immutable release.
HTML projects can import local files and declare exact-version npm dependencies.
The browser compiler reports missing imports and invalid source before a
proposal can be applied or published.

Use Interact to play and Point or Region to annotate. Compiled previews use a
fixed logical viewport so notes stay aligned when panels resize or you zoom.
Annotations retain their revision, normalized geometry, observable game state,
and a private recording snapshot when storage is available. Image and video
annotations in Commons use the artifact's content bounds, including letterboxing.

Record interaction captures DOM/canvas activity for later playback. Recordings
are private by default; opt into spectator sharing before recording to add a
session to the published game's page. Downloaded recordings can also be opened
locally. Recording is bounded to five minutes or 8 MB of event data; it is a
browser replay, not a screen-video encoder, and cross-origin or protected media
may not be captured.

Open a recording in Studio to add a point or region note at the current
playback time. Timeline markers seek back to that exact moment, while the note
retains the same revision and normalized geometry used by live-preview
annotations.

## Agent playtests

For browser games, expose `window.arcade.seats()`, `observe(seatId)`,
`actions(seatId)` and `step(id, seatId)` to give every agent its legal view and
actions. Without a bridge, Studio uses visible button labels and page text.
Fill every supported seat with a human or Commons agent, then run continuously
or one decision at a time. A signed-in human can pause and coach an agent; the
new strategy is versioned and takes effect on its next decision. Sessions and
their per-agent Commons conversations can be resumed later. Browser tests are
private, client-observed, unrated, and never prize eligible. Each session
accepts up to 200 decisions.

Grid templates additionally support the deterministic Test Arena and online
matches with authoritative actions, reconnectable seats and verified replays.
Use `arcade init game.json --template grid` for this runtime.

## From any terminal agent

Create an access key in [Agents](/agents). Give it only the required permissions.
Keys are shown once, expire within 90 days, and can be revoked immediately.
Store the key in your environment, not in source files.

```bash
export ARCADE_API_URL=https://arcade.agentcommons.io/api/arcade
export ARCADE_TOKEN=your_scoped_arcade_key
npm install -g https://github.com/Arttribute/common-arcade/releases/download/v0.1.0-alpha.1/common-arcade-cli-0.1.0-alpha.1.tgz
arcade init game.json
arcade projects create --file game.json
arcade projects get prj_RETURNED_ID
arcade projects update prj_RETURNED_ID --file game.json --revision 1
arcade projects publish prj_RETURNED_ID --revision 2
arcade games search
```

Update and publish require the revision you reviewed. On conflict, read the
latest project and incorporate its changes. The portable
[Common Arcade skill](https://github.com/Arttribute/common-arcade/blob/main/skills/common-arcade/SKILL.md)
documents source files, the browser bridge and external-agent workflows.

## TypeScript SDK

Install the versioned release asset with Node.js 22 or newer:

```bash
npm install https://github.com/Arttribute/common-arcade/releases/download/v0.1.0-alpha.1/common-arcade-sdk-0.1.0-alpha.1.tgz
```

```ts
import { ControlClient } from '@common-arcade/sdk'
const arcade = new ControlClient({
  baseUrl: process.env.ARCADE_API_URL!,
  bearerToken: process.env.ARCADE_TOKEN!,
})
const project = await arcade.createProject({
  kind: 'browser',
  title: 'My web game',
  description: 'Built with my own agent.',
  entryFile: 'index.html',
  files: [
    { path: 'index.html', content: '<!doctype html><button>Play</button>' },
  ],
})
const release = await arcade.publishProject(project.id, project.revision)
const run = await arcade.createBrowserRun(project.id)
```

Use `decideBrowserAction` with a current observation and action ID for your own
agent, or an owned Commons agent ID when creating the run. Execute the selected
action in your browser and submit the next observation. For grid online play,
`claimSeat` and `createSession` return the credentials needed by `RealtimeClient`.

## Larger worlds, teams, and 3D

Browser documents may declare optional `capabilities` for session, campaign, or
persistent worlds; turn, event, window, or fixed-tick cadence; 2D, 3D, or mixed
presentation; team topology and control; and content authored in Blender for
runtime delivery as glTF/GLB and compressed textures. The browser bundle still
runs with the same sandbox and size limits. Blender project files are authoring
inputs, not browser runtime assets.

Economy declarations distinguish `disabled` from `integration-ready` and list
future authorization, escrow, settlement, refund, or ledger hooks. This is
capability metadata only: it never enables money movement, wagering, prizes, or
settlement. Those require a separately reviewed authoritative runtime and
payments integration.

## Copilot hosting contract

Studio Copilot works live-first. It uses a supported Arcade-managed runtime by
default and must run the game test before calling a project live-ready. The test
identifies the runtime module and returns `liveReady: true` only when Arcade can
recreate the rules, state transitions, observations, results, and replay on the
match worker.

If requested mechanics do not fit an installed managed runtime, Copilot may
create a browser preview only after explicitly acknowledging that limitation.
Preview source can still be played and tested privately, but declaring
`authority: arcade-managed` does not make browser JavaScript authoritative.
Connecting that game requires a managed runtime module or a conformant external
host, followed by another successful live-readiness test.

Authoritative match creators choose public, unlisted, or private visibility.
Only public lobbies and active matches appear in [Live](/live); private Studio
agent playtests and unlisted rooms stay out of the feed.

## Hosting and current boundaries

Projects, revisions, annotations and grants persist in DynamoDB. Lambda handles
the control plane; ECS handles authoritative grid matches. Replays use S3 and
can use a self-hosted S3-compatible endpoint. See the
[operator guide](https://github.com/Arttribute/common-arcade/blob/main/docs/operations/creator-alpha.md)
for configuration.

This is an alpha protocol. Browser projects run in isolated client-side frames;
server containers, authoritative arbitrary-code multiplayer, multi-worker
placement and unrestricted package builds remain roadmap work. Projects are
limited to 60 files and 120 KB of source; dependencies use exact versions.

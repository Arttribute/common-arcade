---
title: Repository map
description: What's implemented versus scaffolded across the Common Arcade monorepo.
---

- `apps/` — user-facing or network-facing deployables.
- `services/` — isolated workers for matches, policy, and builds.
- `packages/` — publishable standards, SDKs, runtimes, UI, and adapters.
- `schemas/`, `specs/`, and `rfcs/` — normative design artifacts.
- `infra/` — AWS, Vercel, and local deployment definitions.
- `tests/` — protocol, interoperability, load, chaos, and security suite
  placeholders.

## What's real today

| Area | Status |
|---|---|
| `apps/web` | Public site, Studio, and the Fumadocs docs you're reading |
| `apps/control-api` | Full control plane — games, releases, projects, Studio, matches, Test Arena, Commons integration |
| `apps/mcp-server` | 14-tool MCP server (not yet published to npm) |
| `apps/realtime-gateway` + `services/match-worker` | The live match protocol and sandboxed rules host |
| `packages/protocol`, `manifest`, `match-runtime`, `control-client`, `realtime-client`, `sdk`, `cli`, `studio` | Typed, tested, in active use |
| `packages/policy-ir`, `policy-runtime`, `team-policy`, `adaptation`, `test-arena`, `diagnostics`, `auth`, `conformance` | Real, bounded implementations |
| `examples/tic-tac-toe` | The only example game with full working rules and tests |
| `rfcs/0001`, `rfcs/0002` | Substantive, implemented-in-part RFCs (extensible capabilities; lobbies/series/remixes) |
| `schemas/v0alpha1/` | 11 versioned JSON Schemas served live from the control API |

## What's still scaffolding

| Area | Status |
|---|---|
| `apps/match-supervisor`, `apps/registry-worker`, `apps/studio-orchestrator` | Empty scaffolds — no durable ownership-lease supervisor or registry ingestion yet |
| `services/build-worker`, `services/policy-worker` | Scaffolds, no dependencies wired |
| `packages/adapters/*` (gymnasium, pettingzoo, nakama, agent-commons) | `stability: 'pre-v0alpha', implemented: false` stub exports only |
| `packages/react`, `packages/ui`, `packages/presentation-bridge`, `packages/observability` | Near-empty |
| `examples/duel`, `examples/football-arena`, `examples/swarm-tactics` | README-only placeholders, no code |
| `tests/chaos`, `interop`, `load`, `protocol-vectors`, `security` | README-only placeholders — actual tests live co-located as `*.test.ts` inside packages/apps instead |
| `specs/` | Explicitly non-normative — only the two RFCs and the JSON Schemas are promoted so far |

Every package still marked `pre-v0alpha` is a boundary, not a promise that its
final API has been designed. See [Architecture boundary](/docs/architecture)
for the control-plane/realtime-plane split, or the canonical
[system design document](https://github.com/Arttribute/common-arcade/blob/main/docs/architecture/common-arcade-system-design.md)
for the full decision record.

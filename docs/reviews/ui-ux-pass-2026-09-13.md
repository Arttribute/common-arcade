## Shared UI decisions

- Space Grotesk throughout; Geist Mono for source and technical values.
- Commons sidebar dimensions: 290px open, 60px collapsed; 16px icons, 28px
  collapsed icon buttons with 12px gaps, and 32px/24px wordmark/icon heights.
- Live detail pages automatically collapse the main navigation, like Commons
  workflow details. Game details omit navigation entirely: artwork reaches the
  left edge, with a simple back button over it. Normal navigation remains on
  list pages.
- The Studio editor has a single vertical rail containing Studio tools, with
  hover labels and a back button to leave. General navigation is shown outside
  the editor. Mobile drawers open one at a time. A subtle SVG dot grid on a
  slightly darker preview canvas follows scrolling and zoom, inspired by the
  supplied workflow-canvas screenshot; it adds no gradients or idle animation.
- Commons’ corner hierarchy is shared across cards and controls, with the user’s
  later request for slightly softer edges: 12px cards, 10px buttons/inputs and
  8px small controls (a 2px increase). Panel insets and disclosure gaps
  prevent adjacent control borders from touching. Interface icons use Lucide
  with a common 1.75 stroke; Unicode action glyphs have been replaced.
- Agent choices use the Commons avatar/name switcher with search, a 320px
  scrolling list, selection checks and keyboard navigation. Copilot, test
  players, live seats and wallet budgets share the component. Fallback avatars
  use restrained two-colour pastel blends, following the later 01:14 Commons
  screenshots. The same subtle treatment appears only on game placeholders;
  buttons and application surfaces remain solid.
- One neutral palette, slightly stronger borders, modest radii, black primary
  buttons and restrained colourful artwork. Blue is reserved for links and selected states. Plain page titles replace the earlier
  Commons-style highlights, following the user's latest visual direction.
- Two large artwork-led featured banners lead Discover, restored from the
  supplied App Store-inspired reference. Featured selection uses explicit catalog
  `isFeatured` flags for Redline Run and High Stakes Blackjack, independent of
  popularity or thumbnails. The regular catalogue retains equal
  16:9 cards; Studio uses compact two-column user-created game rows. Missing
  thumbnails show one centred Lucide gamepad on a softly tinted background.
  Whole cards navigate to game details; repeated Play/Explore buttons are removed.
- Game details use equal desktop halves: sticky full-height artwork and an
  overlaid Play shelf on the left; title, description, preview and recordings
  on the right. Mobile uses a stacked layout.
- Copilot user messages have a quiet lavender fill and high-contrast text, using
  shared light/dark tokens.
- Copilot's attachment, agent, model and send controls remain on one line.
  Desktop drawers have a 390px minimum width; smaller layouts truncate labels.
- Editing permissions and computer access live behind a settings icon in Copilot's
  header. Settings open within the panel, with a back action to the conversation.

## Copilot and computer behavior

Studio presents one functional Copilot instead of separate Build and Chat
interfaces. Existing native Commons session connections remain valid. New
conversations are ordinary Commons sessions scoped to the game, owner and agent;
users can select prior conversations and open their full history in Commons.
The selected conversation survives refresh within the browser tab, including
recovery of a run started in a newer conversation.
The project-reading tool exposes saved revision summaries and can inspect a
specific prior revision.

A durable patch to the vendored UI adds Lucide recording-control slots and an
acknowledged readiness probe. Recording now works when the iframe finishes before
React registers its listener, including repeat recording after replay.

The UI defaults to reviewing edits. Manual mode stores proposals without changing
the saved game; approval checks the source revision and claims the proposal
before applying it. Repeated approval is idempotent, stale proposals fail, and
Discuss only denies saved-game mutations. Automatic mode retains direct editing.
Legacy API callers retain their prior automatic behavior.

Concurrent turns in a conversation are rejected. Dispatch failures release the
conversation for retry; reloading recovers durable job progress and messages.
Each run tracks the revision it actually observed. Concurrent edits reject stale
automatic writes and manual proposals; reading a historical revision cannot
rebase a draft. A current-project reread can recover from a conflict, and a
successful write advances the run’s revision.
Async results are scoped to the selected conversation. Drafts typed during a run
or approval are preserved instead of overwritten by the arriving revision.

The computer panel uses a server-side authenticated proxy with owner checks,
origin protection and a narrow route/method allowlist. Opening it does not start
compute. Enable, Start, Sleep and Restart are explicit actions. Commons tokens
are not exposed to browser code. Its files, browser image, terminal and settings
follow Commons' computer configuration.

The request-computer checkbox asks Commons to prepare compute for a run. It is
not a separate security boundary: Commons' existing stream contract has no
per-run computer-tool denylist, so assigned computer tools remain governed by
Commons permissions. Discuss only enforces saved-game editing permissions.

## Live sessions and payments

The worker stops and reattaches agent policies between rounds, continues
maintenance during round breaks, clears held input at transitions, and excludes
lobby, paused and inter-round waiting from the active-play duration budget.
Persisted timing and stale-expiry checks prevent a delayed expiration task from
ending a resumed session incorrectly. Explicit host close and active-play limits
remain respected.

The live game and player panel share a fixed viewport-based desktop height.
Player controls scroll within their panel, and individual players expand or
minimize without resizing the game. The twelve-player browser case verified
identical 812px panel heights with all players expanded. Mobile remains stacked
with a bounded, scrolling player panel.

The final game frame remains mounted. A compact result panel shows the winner,
with scores and round information behind a disclosure; on mobile it sits below
the game. Host-only actions and seated-player votes match backend permissions.

Payment controls separate ordinary free joining from optional host/payment
configuration. Paid setup now shows Host/Join separately, asks for connection
before displaying host fields, and puts agent budgets in a focused dialog.
Budget review shows amount, cap, agent, match scope, expiry and network; addresses
and technical identifiers are available in an additional account-details view.
Ended sessions lead with the winner, allocated reward and claim action; player
cards, events, receipts and refund support stay in a collapsed details section.
Paid results distinguish recorded outcomes, pending settlement,
confirmed escrow allocations and actual withdrawals. Settlement accounting is
persisted from contract events, including winner, platform, creator and royalty
allocations. Explorer links use the receipt's actual supported network; no
synthetic transaction hashes or inferred withdrawal claims are displayed.
Budget review captures a validated immutable payload; authorization submits the
permission shown in that review even if a hidden form emits a reset. Shared
selects reject empty hydration/reset events, and grant purposes are validated.
Budget grants keep their issuing network, so changing the selected network cannot
misroute a later revocation.

  on open, explicit lifecycle requests, permission-disabled controls, browser
  rendering, independently scrolling source and retained operation errors.
